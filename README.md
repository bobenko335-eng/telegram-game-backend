# Telegram Game Backend

Backend-прослойка между игрой (например, сгенерированной в Aippy) и
одним общим Telegram-ботом. Токен бота никогда не попадает клиенту —
он хранится только на сервере как переменная окружения
`TELEGRAM_BOT_TOKEN`.

```
Игрок 1 ─┐
Игрок 2 ─┼─> Game client (браузер) ──> этот backend ──> Telegram Bot API ──> один бот @<username>
Игрок 3 ─┘
```

Каждый игрок отдельно авторизует **своего** Telegram-пользователя у
общего бота — это не общий чат между игроками, а честная 1:1 переписка
каждого игрока с ботом, легально доступная через Bot API.

## Локальный запуск

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
# впишите реальный токен в .env
uvicorn app:app --reload
```

## Деплой на Railway

1. Запушьте эту папку в отдельный GitHub-репозиторий (`.env` в репозиторий
   не попадёт — он в `.gitignore`).
2. В Railway: New Project → Deploy from GitHub repo.
3. В Variables добавьте `TELEGRAM_BOT_TOKEN` (и при желании
   `ALLOWED_ORIGINS` со списком доменов игры через запятую).
4. Railway сам подхватит `Procfile` и запустит `uvicorn`.
5. Данные (`data.json`) хранятся на локальном диске контейнера — при
   передеплое они теряются. Для постоянного хранения подключите Railway
   Volume и укажите `DATA_FILE=/data/data.json`, либо замените
   `storage.py` на настоящую БД (Postgres/Redis).

## Как это работает (авторизация)

1. Игра вызывает `POST /api/link/start` → получает `game_user_id`,
   `link_token`, `deep_link` (`https://t.me/<bot>?start=<link_token>`).
2. Игра показывает игроку кнопку/ссылку "Войти через Telegram" =
   `deep_link`.
3. Игрок переходит в Telegram, бот присылает "Пожалуйста, авторизуйтесь"
   со штатной кнопкой "Поделиться контактом".
4. После подтверждения бот получает `telegram_id`, имя, username,
   телефон — **только то, что реально передал Telegram** — и
   привязывает их к `game_user_id`.
5. Backend пушит игре через WebSocket событие `linked` с этим профилем.
6. Игра может показать игроку, какие именно данные бот получил
   (`GET /api/profile/{game_user_id}`).

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/health` | проверка живости |
| GET | `/api/bot-info` | `{ "username": "..." }` |
| POST | `/api/link/start` | создать сессию авторизации |
| GET | `/api/link/status/{link_token}` | статус `pending`/`linked` + профиль |
| GET | `/api/profile/{game_user_id}` | профиль, флаг блокировки, привязан ли |
| POST | `/api/block/{game_user_id}` | заблокировать (игра перестаёт получать/слать) |
| POST | `/api/unblock/{game_user_id}` | разблокировать |
| GET | `/api/messages/{game_user_id}?since=&limit=` | история сообщений |
| POST | `/api/messages` | `{ game_user_id, text }` → отправить игроку через бота |
| WS | `/ws/{game_user_id}` | реалтайм-события: `{"type":"linked",...}`, `{"type":"message","message":{...}}` |

## Ограничения Telegram Bot API (важно для игры)

- Бот видит только сообщения, отправленные **ему самому** (личка) —
  полноценным клиентом-читалкой всей переписки пользователя он быть не
  может.
- Через кнопку "Поделиться контактом" бот получает конкретные поля
  (имя, телефон, id), а не "весь аккаунт".
- "Блокировка" в игре — это локальный флаг на backend, который просто
  перестаёт пересылать сообщения в обе стороны; настоящей блокировки
  бота пользователем Bot API не предоставляет.
- Групповые чаты между несколькими игроками через одного бота не
  реализованы — исходный сценарий поддерживает раздельные 1:1 диалоги
  каждого игрока с общим ботом, что и есть единственный легальный
  способ иметь "один бот на всех".
